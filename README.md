# Mixed-Radix FFT (Быстрое преобразование Фурье)

Данная программа реализует **быстрое преобразование Фурье (FFT)** для комплексных чисел с поддержкой длин преобразования, разлагающихся на простые множители **2, 3 и 5**. 
Алгоритм использует **Mixed-Radix** подход (смешанные основания), что позволяет эффективно обрабатывать сигналы длины, отличные от степени двойки.

### Mixed-Radix
В отличие от классического FFT, который работает только с длинами, равными степени двойки, данный алгоритм поддерживает длины, разлагающиеся на множители **2, 3 и 5**.
**Примеры допустимых длин:**
- 16 = 2⁴
- 18 = 2 × 3²
- 20 = 2² × 5
- 24 = 2³ × 3
- 30 = 2 × 3 × 5
- 60 = 2² × 3 × 5

### Алгоритм «бабочка» (butterfly)
Основной вычислительный элемент FFT — это «бабочка». Для каждого множителя (2, 3 или 5) выполняется своя операция комбинирования групп чисел с использованием **поворачивающих множителей** (twiddle factors).
Поворачивающий множитель — это комплексное число `e^{-2πi·r·k / radix}`, которое задаёт поворот на определённый угол.

##  Структура кода
### Класс `MixedRadixFFT`

| Метод | Описание |
|-------|----------|
| `forward(input)` | Прямое преобразование Фурье |
| `inverse(input)` | Обратное преобразование Фурье |
| `computeRelativeError(original, reconstructed)` | Вычисление относительной ошибки восстановления |
| `computeMaxError(original, reconstructed)` | Вычисление максимальной абсолютной ошибки |

### Вспомогательные функции
| Функция | Описание |
|---------|----------|
| `generateRandomComplexVector(n, minVal, maxVal)` | Генерация случайного комплексного сигнала |
| `printVector(vec, name, maxItems)` | Ввывод вектора комплексных чисел |

### Основная программа (`main`)
- Задаётся длина преобразования `N` (по умолчанию 30)
- Генерируется случайный комплексный сигнал
- Выполняется прямое → обратное преобразование
- Вычисляются ошибки восстановления
- Выводятся результаты

### Почему выбран порог relativeError < 1e-14?
Тип double в стандарте IEEE 754 имеет 53 бита мантиссы, что обеспечивает машинную точность примерно 2^(-53) ≈ 1.11e-16. Это предел точности чисел в компьютере. Но при выполнении FTT происходит накопление ошибок мз-за округления, т.к. FFT выполняет около
n * log2(n) операций (с плавающей точкой). Каждая итеррация добавляет ошибку порядка 1e-16. Поэтому я выбирал порог в 100 раз больше машинной точности (1e-14 вместо 1e-16), что обеспечивает запас прочности против накопления ошибок при большом количестве
операций. Реальные ошибки в тестах лежат в диапазоне 1e-16…5e-16, поэтому порог 1e-14 даёт запас в 20-100 раз. Если ошибка превышает 1e-14 то значит что то не так.

###  Почему выбраны такие ограничения double minVal = -10.0, double maxVal = 10.0
Размах сигнала составляет 20, а величина младшего бита double ~2e-16, что даёт теоретическое отношение сигнал/шум около 340 дБ. Если выбрать меньший диапазон [-1, 1], то амплитуда сигнала будет меньше, => приведёт к худшему использованию битов мантиссы
и потере точности при сложениии или вычитании. Если выбрать больший диапазон [-1000, 1000], возникает риск переполнения при промежуточных вычислениях. Поэтому выбрал [-10, 10] думаю это обеспечит достаточный динамический диапазон для тестирования,
минимальный риск переполнения. 
Вспомним чтопреобразование Фурье линейно (FFT(k*x) = k * FFT(x)), а амплитуда в частотной области примерно в √n раз больше входной. Для n=1024 максимальное значение в частотной области составит около 320, а при x∈[-10,10] пиковые значения достигают
~3200, что остаётся безопасным для типа double.
